# V4.5 source-cohort quarantine

This follow-up is based on draft PR #419. It retains the original 49 scientific
source files and all original model/seed/parameter/study bytes. It does not open
an old real-lottery test partition, start a new model search, add a prediction
model to the registry, install a second ledger, or activate a new challenger.

The disclosed DLT `SCRAMBLED_PAIR_STRONG / R46-REPLICATED-PAIR` negative control
has 69 hits in 2880 synthetic targets, versus 42 for its same-target NULL. The
original 12-cell Holm result remains approximately 0.034141. Reproducing the
generator, prefix predictions, score and arithmetic is not a causal explanation
or a clearance. Its scientific result remains FALSIFIED_REPRODUCED_NOT_FIXED,
cause UNRESOLVED, A0 and NO_EDGE. The synthetic negative 12, historical research
families and missing original formal 12 are separate namespaces.

`promotion.py` anchors the failed experiment by raw plan SHA, canonical content
SHA and exposed synthetic source SHA. Descendants retaining that source lineage
cannot be promoted. A different serialization, a new successful seed, a larger
comparison family, a local integrity PASS or a caller-written clearance cannot
remove the failure. Unrelated versions sharing a model name are not quarantined
by name. Unavailable or unauthenticated lineage is not positive clearance.

The existing AgentContext audit tool and JSON/HTML report now include the fixed
quarantine registry and empty selection boundary. The existing graph report
reader independently requires those fields. The gate's sources are part of the
native code pin, so prior cached reports are not silently relabelled as current.
There is still no formally admitted promotion path. At most one new primary
challenger may be proposed per whole round, across both games; zero are activated.

`reference_models.py` is mathematical reference only: no candidate numbers,
CLI, registration, model search, SQLite writes or real-history evaluation.
Its fixed-size subset formulas demonstrate coherent pair inclusion vectors.
These are new audit reference definitions, not relabelled R45/R46 models or
original eight-slot producers. Rank-only original models cannot acquire Brier
scores from these references without a separately frozen probability contract.

`statistics.py` checks both distinct D2 numbers, full 528/595 pair Brier vectors,
fixed-n paired summaries, conditional exact discordant-pair tests and a complete
explicit 12-ID Holm contract. That structural contract cannot replace the absent
original formal family IDs/SHA. Probability range/degree/sum checks are necessary,
not sufficient to prove every arbitrary vector has a joint distribution. The
conservative Hoeffding interval and paired tests state their independence and
fixed-design assumptions. They do not authorize optional stopping or an edge.

`ledger_faults.py` runs four real OS-process scenarios on one newly created
fixture ledger using the unchanged, SHA-pinned V4.5 Store: a parent kills an
owned child before the real COMMIT, kills after append returned True, then
releases two processes at a common barrier for equal and conflicting payloads.
The first scenario uses a test-only two-page cache and large fixture payload to
force uncommitted WAL frames. The child keeps an anchor connection open. Before
recovery, the parent captures DB+WAL bytes; the WAL parser validates salts and
cumulative checksums against the SQLite file-format specification. The parent
never accepts a caller-supplied database or PID. All owned workers have bounded
waits and are reaped. Python optimization is rejected because it would remove
the harness assertions. No production ledger or lottery history is opened.


The four process scenarios supplement the scoped unit suite; they are not four
more unique unit tests or the complete nine P0 tests. Process termination does
not establish physical power-loss durability, real boot, elapsed PT30M,
network-disconnect recovery, Windows 11 or candidate/TSA admission. Those gates
remain NOT_RUN/BLOCKED. The 49 frozen science sources remain unchanged.

The separate verifier imports neither Store nor the producer's WAL parser. It
recovers captured DB+WAL pairs using native SQLite in disposable copies, reads
the closed final fixture with immutable read-only mode, checks worker/phase
receipts and confirms every input byte remains unchanged. It does not claim an
independent hardware witness or recompute the producer's frame-count metadata.
Counterexamples include zero-exit kill claims, relabelled raw phase evidence,
rehashed corrupted committed WAL and Python optimization removing assertions.
