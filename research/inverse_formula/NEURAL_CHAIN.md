# Six-expert evidence-chain V3 — research only

This is an explicit six-role, two-round decision graph, not a biological
neural network or a trainable foundation model. It does not expose a model's
private internal reasoning. User-visible distillation consists of observable
hypothesis summaries, bounded formulas, peer objections, vetoes, vote weights,
history cutoffs and reproducible audit checks.

## Six specialist functions

1. Mathematician — constrained recurrence and falsifiability.
2. Formula discovery — inspect prior, dated formulas and propose alternatives.
3. Combination researcher — redundancy, ensemble concentration, vote diversity.
4. Statistician — random D2 reference, leakage and multiple testing cautions.
5. Skeptical reviewer — independent adversarial scrutiny and rejection votes.
6. Engineer — deterministic schema, number legality, cutoff and receipt integrity.

The six proposal requests run independently before the six cross-review
requests, each considering formulas submitted by other roles. Identical
formulas are deduplicated. Three unique external reject votes veto a formula.
No model-generated Python or shell code is executed; only validated
declarative integer recurrences are interpreted. The remaining formulas
are aggregated deterministically into a research ticket and explicit dan/sha
heuristic lists. Neither dan nor sha has a proven future inclusion/exclusion
advantage.

## Implemented modules

- research/inverse_formula/live_council_v2.py: parallel proposals, individual
  reviewer evaluations, veto counts and deterministic aggregation.
- research/inverse_formula/neural_audit.py: independently recomputes role IDs,
  formula IDs, candidate tickets, review edges, vetoes, final vote and receipt
  digest; produces formula registry, public evidence graph and past-only
  deterministic-bank reference.
- research/inverse_formula/one_click.py: performs both games' source checks,
  then their role meetings, evidence graph generation, research content seals
  and the combined report and manifest.
- research/inverse_formula/closure.py: validates and scores a content seal
  after a caller supplies an independently checked winning result.

The live OpenAI council has six role-specific API requests per round,
two rounds per game, four rounds / 24 possible paid requests per two-game run.
It uses five different GPT-6-series model IDs across six roles. Model-family
bias is not eliminated by separate calls.

## Honest prospective boundary

The six GPT formulas are first proposed AFTER all historical data through
the as-of issue have been shown. Therefore replaying them on that known
history is descriptive, NOT a true historical forecast test. Each formula
registry row stores proposed_after_issue, first_eligible_prospective_issue and
prospective_observation_count=0.

Only new outcomes following an externally published pre-draw receipt can be
scored as genuine prospective observations. The rolling past-only baseline
inside the evidence graph belongs to the PRE-EXISTING deterministic formula
bank, not to these newly proposed GPT formulas, and is not the formal V4.7
fixed Random NULL.

SHA256 is for integrity, not trusted timestamping. Model response IDs are
correlation records, not independent proof of model authenticity or billing.
The official result source still needs independent verification. Any claim of
predictive advantage remains NO_EDGE.

## Validation gates

- Six roles present, correct GPT-6-series models and high effort.
- Independent proposal and full peer-review structures.
- Formula IDs, bounded tickets, D2 and dan/sha legality.
- All distinct peer votes and veto/weight/consensus recomputation.
- Missing, changed or future outcomes never silently substituted.
- Missing API credentials or standing paid approval must abort before calls.
- Fail-closed if a receipt is altered, output path exists, or all formulas vetoed.
- Ubuntu + Windows mocked test matrix and cross-OS research seal consistency.

Formal V4.7 forecasts, frozen official ledger and original fixed Random NULL
must remain untouched. Draft PR #470 stays unmerged. Live API calls and
real prospective superiority remain UNVERIFIED without independent evidence.
